## 목표

- 단일 HTML을 SvelteKit + TypeScript 프로젝트로 옮긴다. 화면과 동작은 원본과 같게 유지한다.
- 웹 호스팅 + 폰 설치(PWA)로 쓴다. 정적 빌드라 어느 정적 호스팅에도 올릴 수 있다.
- 원본 검토에서 찾은 버그 1~4를 고친다.

## 버그 수정

1. **음성**: 화자가 다르면 다른 음성을 배정한다. 남성 음성 이름 목록을 넓히고, 음성이 모자라면 음 높이로 구분한다.
2. **채점 방식**: Day의 첫 답을 고를 때 방식을 고정한다. 설정 변경은 새로 시작하는 Day부터 적용된다.
3. **첫 점수**: 첫 시도가 끝날 때 점수를 저장한다. 결과 화면에 "첫 점수 → 현재 점수", 목차에 완료 상태를 유지한다.
4. **기록 가져오기**: Zod로 검사하고 덮어쓰기 전에 확인한다. 원본(v1) 형식도 받는다.

## 기록 형식 (v2)

```ts
{
  version: 2,
  settings: { mode: 'instant' | 'exam', rate: 0.8 | 1 },
  days: { [day]: { page, answers, graded, retry, mode, firstScore } }
}
```

- `mode`: 첫 답을 고를 때 고정 (그 전에는 `null` → 현재 설정을 따름)
- `firstScore`: `{ correct, total }` 또는 `null`
- 원본 기록은 원본 파일의 "기록 내보내기" → 새 앱의 "기록 가져오기"로 옮긴다 (출처가 달라 자동 이전 불가).

## 진행 순서

1. 골격 + 시험 빌드 → 빌드·오프라인 동작 확인
2. 데이터 이전 (변환 스크립트는 임시 폴더에서 한 번만 실행) → Zod 검사 통과, 원본과 문항·정답 전부 일치
3. 화면 이전 → Playwright로 Day 열기·답 고르기·채점·재풀이·내보내기/가져오기 확인
4. 버그 1~4 수정 + 회귀 테스트
5. 마무리: `check`, `lint`, `test`, `build` 전부 통과

## 결과 (2026-10-21)

- 데이터: 변환한 40개 Day 파일이 원본과 깊은 비교로 완전히 같음 (1,000문항, 커리큘럼 포함)
- 화면: 원본과 같은 상태로 캡처해 비교. 목차·레슨·Part 3/5/6·결과 화면 배치와 색이 같음
- 바뀐 점: 보기의 정답/오답에 ✓/✗ 아이콘, 채점 방식 설정 아래 안내 문구, 결과 화면의 "첫 점수" 줄, 버튼 아이콘(Lucide)
- 성능: gzip 서빙 기준 첫 로딩 2.5초(Slow 4G), 1.1초(Fast 4G), 전송 390KB. 이후는 서비스 워커 캐시
- 테스트: 단위 321개(콘텐츠 검사 포함), Playwright 10개 통과
- 남은 확인: 실제 폰(안드로이드·iOS)에서 음성과 설치 동작 — 자동 테스트로는 음성을 흉내 낼 수 없음
