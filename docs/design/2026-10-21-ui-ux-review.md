## 3. 설계 결정과 이유

### 3.1 화면 구조

- 하단 탭은 오늘 · 문제집 · 단어장 · 복습이다. 1차에서는 단어장 탭을 숨긴다.
- 아이패드 가로(768–1279px)는 왼쪽 레일, PC(1280px 이상)는 사이드바를 쓴다.
- 설정은 오늘 화면 오른쪽 위 버튼으로 연다. 큰 화면에서는 메뉴 아래에 둔다.
- 주소는 `/` 오늘, `/days` 문제집, `/day/숫자` Day, `/review` 복습이다. `/day/숫자`는 설치한 앱과 북마크 때문에 유지한다.

### 3.2 문제집 학습

- **Day 시작 화면:** 목표, 주제 묶음별 바로가기(개념 / 따라 풀기 / 실전), 이번 풀이의 채점 방식을 보여 준다. 채점 방식은 첫 답 전에만 바꿀 수 있고, 다시 풀기에서는 바뀌지 않는다.
- **풀이 화면:**
  - 상단: 제목, '실전 n / 25', 25문항 점 막대
  - 버튼: 개념 다시 보기(시트), 문항 지도(시트)
  - 하단 바: 깃발, 이전, 다음
- **문항 지도:** 묶음별 문항 칸에 맞힘 / 틀림 / 답함 / 안 풂 상태와 깃발을 보여 준다. '지금까지 결과 보기'도 여기서 연다.
- **Part 6·7:** 휴대폰은 지문을 위에 고정하고 문제를 하나씩 넘긴다. 큰 화면은 두 칸으로 놓고, 답한 문제를 한 줄로 접는다.
- **Part 3·4:** 듣는 동안 문제를 미리 읽어야 해서 세트 문제를 한 화면에 모두 둔다.
- **듣기:** 큰 재생 버튼, 듣는 순서 표시, 처음부터 다시 듣기, 화면 안 속도(0.8배 / 1배)를 둔다. 영어 음성이 없는 기기를 위해 '스크립트 보기'는 남긴다.
- **결과:** '첫 점수 → 현재 점수', 파트별 점수, 아직 틀린 문제, 다음 할 일(다음 Day).

### 3.3 복습

- 모든 Day에서 틀린 문제를 Day별로 모은다. 틀린 횟수를 함께 보여 준다.
- 복습에서 맞히면 목록에서 빠지고 그 Day의 현재 점수가 오른다. 첫 점수는 그대로다.
- 기존 기록의 틀린 문제도 처음 열 때 바로 들어온다.
- 깃발은 Day 안에서만 쓴다.

### 3.4 색과 접근성

- 강조색 #2556C4, 누름 #1A3F94, 연한 파랑 #EAF0FD를 쓴다.
- 정답 #1D7A43, 오답 #B42318, 깃발 #C2410C. 정답과 오답은 아이콘과 글자를 함께 쓴다.
- 바탕 #F5F6F4 위에 흰 카드를 놓는다. 글꼴은 시스템 글꼴을 유지한다 (오프라인 때문).
- 터치 영역은 44px 이상이다. 영어 문장에는 `lang="en"`을 붙이고, 판정은 `role="status"`로 읽어 준다.

### 3.5 키보드

| 키    | 동작                                            |
| ----- | ----------------------------------------------- |
| ← / → | 이전·다음 (휴대폰 세트에서는 세트 안 문제 먼저) |
| ↑ / ↓ | 아이패드·PC 세트에서 문제 이동                  |
| 1–4   | 보기 선택                                       |
| Space | 듣기 재생 (버튼에 포커스가 없을 때)             |
| F     | 깃발                                            |
| G     | 문항 지도                                       |
| Esc   | 시트 닫기                                       |

시트가 열려 있거나 입력 칸에 있을 때는 단축키를 무시한다. 한글 입력 상태에서도 F와 G가 되도록 키 위치(`event.code`)로 판정한다.

### 3.6 시안과 계획이 달라진 점

검토 과정에서 시안의 일부를 바꾸거나 뺐다.

| 시안                                           | 계획                                | 이유                                                             |
| ---------------------------------------------- | ----------------------------------- | ---------------------------------------------------------------- |
| 지문 위 '해석' 버튼을 풀기 전에도 누를 수 있음 | 세트 문제를 모두 공개한 뒤에만 연다 | Part 6 해석에 정답 단어가 그대로 있다 (예: d17-13)               |
| Part 3·4도 한 문제씩                           | 세트 문제를 한 화면에 모두          | 듣는 동안 문제를 읽어야 한다                                     |
| '3일째 이어서 공부 중'                         | 넣지 않음                           | 기록에 날짜가 없다                                               |
| Noto Sans KR 글꼴                              | 시스템 글꼴                         | 서비스 워커가 다른 출처 파일을 캐시하지 않아 오프라인에서 바뀐다 |
| 판정 문구 '틀렸어요 · 정답은 (C)'              | 기존 '오답입니다 · 정답 (X)' 유지   | 바꿀 이유가 없고 기존 검사와 맞다                                |
| 응답 글자는 고른 뒤에만                        | '스크립트 보기' 유지                | 영어 음성이 없는 기기에서도 풀 수 있어야 한다                    |
| 다시 풀 때 채점 방식 변경 가능                 | 처음부터 다시 풀기 뒤에만 변경      | 채점 방식 고정 규칙과 회귀 테스트가 있다                         |

## 4. 코드 조사 결과

구현 전에 알아야 할 사실이다. 출처는 2026-10-21 저장소 조사이다.

### 4.1 저장 형식

- 기록은 localStorage `toeicBasic.v2`에 있다. Day마다 `page`, `answers`, `graded`, `retry`, `mode`, `firstScore`를 저장한다.
- `parseProgress`는 v2 검사에 실패하면 v1으로 다시 검사한다. v2 기록은 v1 검사도 통과한다. 그래서 새 필드를 필수로 두거나 엄격하게 검사하면 기존 기록이 v1으로 다시 변환되고, 첫 점수와 채점 방식이 다시 계산된다.
- Zod `z.object`는 스키마에 없는 필드를 지운다. 예전 코드가 열린 탭이 저장하면 새 필드가 사라진다.
- `replaceProgress`는 `settings`와 `days`만 옮긴다.
- 결론: 새 필드는 모두 선택 항목이고, 잘못된 값은 기본값으로 바꾼다. 가져오기와 내보내기도 새 필드를 옮긴다.

### 4.2 페이지 위치

- 저장된 `page`는 `[표지, ...내용 페이지, 결과]` 목록의 위치이다. 표지가 0번이다.
- 다시 풀기 중에는 표지 없이 다시 푸는 문제가 있는 페이지만 남는다.
- 결론: Day 시작 화면은 표지 자리에 그린다. 그러지 않으면 저장된 위치가 한 칸씩 어긋난다.

### 4.3 '지금 틀린 문제'의 뜻

- 답이 있고, 정답이 아니고, 공개된 문제가 틀린 문제다. 공개는 채점됨, 또는 바로 채점에서 답한 상태다.
- 기존 데이터만으로는 부족한 경우:
  - 다시 풀기를 시작하면 틀린 답이 지워져 '틀림'이 '안 풂'이 된다.
  - 채점된 시험의 빈 답은 점수에서는 틀림이지만 답이 없다.
  - '몇 번 틀렸는지'는 기록에 없다.
- 결론: 문항별 틀린 횟수(`misses`)를 새로 저장한다. 기존 기록은 불러올 때 계산해 채운다.

### 4.4 주제 묶음

Day의 페이지 순서로 묶음을 계산하면 다음과 같다.

| Day   | 묶음 수 / 커리큘럼 주제 수 | 특이점                                                |
| ----- | -------------------------- | ----------------------------------------------------- |
| 1–16  | 2 / 2                      | 묶음과 주제가 맞음                                    |
| 17–24 | 3 / 2                      | 셋째 묶음(Part 2 복습)은 주제가 없어 레슨 제목을 쓴다 |
| 25–36 | 3 / 3                      | 따라 풀기가 없다                                      |
| 37–40 | 1 / 1                      | 여러 파트가 섞인 한 묶음, 따라 풀기 없음              |

### 4.5 부품과 도구

- shadcn의 sheet 템플릿은 설치되어 있지 않고, 인터넷 레지스트리에서만 받을 수 있다. bits-ui의 Dialog와 Collapsible은 설치되어 있어서 sheet를 직접 만든다.
- 단위 테스트는 Node 환경만 있고 컴포넌트 테스트 도구가 없다. 새 로직은 순수 TS로 쓴다.
- 기존 e2e 10개는 모두 바뀌는 화면 구조(홈 제목, 쪽수 표시, CSS 클래스, `main`·`h1` 개수)에 기대고 있다.
- 지금 테마의 primary는 '연한 민트 바탕 + 진한 글자'이다. 진한 파랑으로 바꾸면 고른 보기, PageTag, 설정 토글, 헤더가 대비를 잃어 따로 고쳐야 한다. theme-color(`app.html`, manifest)와 아이콘도 민트다.
- 서비스 워커는 prerender된 페이지를 모두 미리 캐시한다. 새 주소도 자동으로 들어간다.
- 키보드 처리에는 시트나 입력 칸을 막는 장치가 없다. 한글 입력 상태에서는 F 키의 `event.key`가 'ㄹ'이다.

## 6. 2차 단어장 검토 (PDF)

### 6.1 PDF 구조

- 21쪽이다. iOS에서 만든 표 형식이고, 1쪽은 2쪽(Week 1 Day 1)의 표시 없는 중복본이다.
- Week 1–4 × Day 1–5 = 20 Day이고, Day마다 49~52단어, 모두 약 1,000단어이다.
- 열은 번호 · 단어 · 발음기호 · 품사(명/형/부/자/타/동) · 뜻(괄호 안 용법 포함)이다.
- 문법 내용은 없다. 문법은 문제집 40 Day가 맡는다.

### 6.2 텍스트 추출

- 영어 단어와 번호는 PDF 텍스트에서 그대로 뽑힌다.
- 한글 뜻과 발음기호도 텍스트 층에서 정확히 복원된다 (2026-10-23 확인). 글자가 깨져 보인 것은 ToUnicode 매핑이 비어 글리프 ID만 남았기 때문이다. 임베디드 글꼴의 글리프가 Windows 글꼴(맑은 고딕, Lucida Sans Unicode, Calibri, Arial, MS Gothic)과 바이트 단위로 같아서, 시스템 글꼴의 cmap을 거꾸로 읽으면 표의 1,012줄(번호 있는 1,006줄 + 이어진 줄 6줄)에서 복원 못 한 글자가 0이다. 이미지 판독은 표본 확인에만 썼다.
- 3쪽 50번 versatile도 복원된다. 3쪽은 표 아래 테두리가 없어서 마지막 줄을 따로 처리해야 한다.
- 번호 칸의 `、45`, `:9`, `∞40` 같은 이상한 글자는 iOS 손글씨 인식이 숨겨 둔 글자다. 글꼴 이름(`.SFUI`, `AppleSDGothicNeo`, `AppleSymbols`)으로 걸러 낸다.
- 번호 없는 이어진 줄은 앞 단어의 품사 묶음이다. 발음기호가 두 줄인 단어(15쪽 economical, 17쪽 alternative)는 한 칸으로 붙였다.
- 원본 자체에서 발음기호가 잘린 단어가 셋 있다 (cooperative, independent, presentation). 그대로 둔다.
- 파일명이 한글이라 Git Bash에서 Python 인자로 넘기면 깨진다. 스크립트 안에서 `glob`으로 연다.

### 6.3 판독과 검수 절차

텍스트 층 복원으로 판독 단계가 없어져 절차를 줄였다 (2026-10-23).

1. 텍스트 층과 벡터 획에서 Day별 데이터를 한 번 추출한다. 추출 스크립트는 프로젝트 밖에 두고, 결과 `src/lib/content/words/wXdY.ts`가 원본이 된다.
2. 개수와 ID는 `src/lib/content/words.test.ts`가 고정한다: 1,006줄, 고유 1,000단어, Day별 줄 수, ID 순서.
3. 번역 검수: 다른 에이전트가 단어마다 한글 뜻과 품사가 그 단어에 맞는지 판정했다. 원본 오기 의심 28건 가운데 사용자가 확인한 25건(뜻·품사 16건, 맞춤법 9건)을 고쳤다. 확신이 낮은 3건(perishable, allowance, congestion)은 원본 그대로다.

### 6.4 색 표시 (학습 상태)

- 범례(2쪽 위): 노랑 = 완벽, 베이지 = 중간·애매, 초록 = 처음
- 번호 동그라미의 실제 색: 완벽 #FFFF80, 애매 #ECD6AC, 처음 #BCE2A0
- 펜 표시는 모두 벡터 획이라 픽셀 대신 획의 색과 굵기로 판정한다. 동그라미는 번호 칸의 작은 획(굵기 10.65, 너비 30pt 미만)이고, 16·36번 줄의 노란 띠(의미 없음, 사용자 확인)는 넓은 별도 획이라 섞이지 않는다.
- 확정값 (2026-10-23, 줄 기준): 처음 248 · 애매 608 · 완벽 148 · 동그라미 없음 2 (14쪽 balance, besides). 예전 픽셀 판정 초안(218 · 563 · 168 · 54)은 띠와 여백 점이 섞인 값이었다.
- Day 끝 두 단어가 다음 Day 끝에 다시 나오는 3쌍(take off · temporary, value · voucher, troubleshooting · urban)은 기록 하나를 함께 쓴다 (사용자 결정).
- 처음에는 PDF 색을 앱의 첫 학습 상태로 가져왔지만, 2026-10-23에 바꿨다 (사용자 결정). 이제 PDF 단어는 모두 '처음'에서 시작하고, 앱에서 바꾼 값만 남는다. 색은 단어 데이터에 넣지 않는다. 문제 해설에서 담은 단어 가운데 PDF에 없는 단어는 '안 봄'에서 시작한다.
- 다른 펜 표시 (사용자 결정):
  - 파란 형광펜(8단어, 단어 칸) = 중요 → 별표
  - 회색 형광펜이 뜻 하나에 칠해진 15곳 = 핵심 뜻 → 굵게 강조
  - 회색 형광펜이 단어 칸에 칠해진 9단어, 왼쪽 여백의 점, 빨간 낙서 = 의미 없음

### 6.5 단어장 화면 설계 (시안)

- **목록:** PDF 순서대로 보인다. 다 보기 / 뜻 가리기 / 단어 가리기를 고르고, 줄을 눌러 하나씩 확인한다. 상태 칩을 눌러 상태를 바꾸고, 상태별로 거르고, 발음을 듣는다.
- **카드:** 앞면(단어·발음) → 뒤집기 → 뒷면(품사별 뜻)에서 처음 / 애매 / 완벽을 고른다. '처음'은 세션 끝에 한 번 더 나오고, 끝나면 요약을 보여 준다.
- **복습:** 처음·애매 단어를 오래 안 본 것부터 20개씩 보여 준다.
- **상태 색:** PDF 범례 그대로 쓰고, 색만으로 구분하지 않게 글자와 아이콘을 함께 쓴다.

### 6.6 단어시험 (2026-10-26)

계획: `docs/plans/2026-10-26-1854-feat-word-test-plan.md`

- **설정:** 단어장의 '단어시험'에서 범위(전체 · Week · Day · 담은 단어 · 별표)와 문항 수(10 / 20 / 50)를 고른다. 처음에는 오늘의 단어 Day와 20문항이 골라져 있다. 낼 단어가 없으면 시작 버튼을 끄고 이유를 보여 준다.
- **문제:** 한 화면에 한 문제. 뜻(품사 포함)과 첫 글자 힌트(`t _ _ _   o _ _`)를 보고 영어를 쓴다. 정답이 새지 않게 뜻의 영어 괄호는 지운다. 다 풀고 '채점하기'로 한 번에 채점한다.
- **결과:** 점수, 틀린 단어(정답 · 내 답 · 원래 뜻), 틀린 단어만 '카드로 다시 보기'. 시험 자체는 아무것도 저장하지 않고, 카드에서 매긴 상태만 기록에 남는다.
- **입력 규칙:** 입력칸은 시험 내내 하나라 휴대폰 키보드가 닫히지 않는다. 이전 / 다음 / 채점하기는 키보드에 가리지 않게 입력칸 바로 아래에 둔다. 글자는 16px 이상(iOS 확대 방지), 자동 대문자·자동 수정·맞춤법 검사는 끈다. 한글 조합을 끝낸 Enter는 문제를 넘기지 않는다.
- **스크린리더:** 문제가 바뀌어도 포커스는 입력칸에 남고, 입력칸 이름은 그 문제의 뜻이다. "문제 n / N"과 뜻을 알리고, 힌트는 "첫 글자 t, 4글자"처럼 읽힌다.

## 9. 1차 계획 문서 검토 결과

검토자 다섯(일관성, 실현 가능성, 디자인, 범위, 반론)이 계획을 읽었고, 남은 의견은 새 검토자 한 명이 따로 확인했다. 다른 회사 모델로 하는 교차 검토는 이 PC에 해당 도구가 없어서 하지 않았다.

### 9.1 계획에 반영한 것 (20건)

- **저장 데이터와 복습:**
  - 시험 다시 풀기 중인 Day는 복습에서 뺀다. 빼지 않으면 다시 푼 답의 정답 여부가 복습 목록에서 드러난다.
  - 기존 기록의 틀린 횟수를 보충하는 규칙에 채점된 빈 답과 '전체 보기'로 비어 버린 답을 더했다.
  - '시작 전' 기준을 상태 문구와 같게 맞췄다 (답 없이 채점된 Day의 채점 방식이 바뀌지 않게).
  - 문제집 목록에서 채점 전 시험 Day가 점수를 미리 보이지 않게 했다.
- **요구사항 문장:**
  - 문항 지도는 다시 풀기 중에는 다시 푸는 문항만 누를 수 있다.
  - '틀린 문제만 다시 풀기'는 첫 점수가 생긴 뒤에만 보인다.
  - 지문과 문제를 나란히 놓는 것은 1024px 이상(아이패드 가로·PC)이다.
  - 시트가 열렸을 때 G와 Esc는 시트를 닫는다.
- **화면 규칙:**
  - 휴대폰 지문 패널은 내용 영역의 약 40%이고, '크게 보기'로 키운다.
  - 휴대폰 세트에서는 하단 이전/다음이 세트 안 문제를 먼저 옮긴다.
  - 아이패드 세로는 휴대폰식 세트 배치를 쓴다.
  - 복습 세션은 시작할 때 문항 목록을 고정하고, 판정과 해설을 본 뒤 '다음'으로 넘어간다.
  - 세트 문제를 복습할 때는 지문과 틀린 문제만 보인다.
  - 점 막대와 문항 지도에 읽을 수 있는 이름과 44px 터치 영역을 둔다.
  - 페이지를 옮기면 포커스를 제목으로 옮기고, 주소가 바뀌면 내용 영역을 맨 위로 돌린다.
- **검증 순서:**
  - 세 화면 크기 e2e를 U4부터 돌린다.
  - 가로 스크롤 검사는 내용 영역까지 본다.
  - 다른 단위 화면에 기대던 테스트를 그 화면을 만드는 단위로 옮겼다.

### 9.2 반영하지 않은 것

- 'Day 시작 화면의 이어서 하기는 저장 위치로 가야 한다'는 의견: 시작 화면에 오면 저장 위치가 시작 화면 자신이 되므로, 첫 미답 문항으로 가는 지금 규칙이 맞다.
- '크게 보기와 Part 6 빈칸 스크롤은 요구사항 밖'이라는 의견: '크게 보기'는 설계 시안에 있다. 빈칸 스크롤이 없으면 Part 6를 한 문제씩 풀 수 없다.
- '화면 종류별 하단 바 구성' 의견: 키보드 규칙 표에서 바로 알 수 있어 따로 적지 않았다.

### 9.3 결정을 기다리는 제안 (3건)

1. **v1 기록 가져오기:** 원본 앱에서 다시 풀기 도중이던 Day는 첫 점수가 비어 있다. 새 규칙(첫 점수가 있어야 다시 풀기 버튼이 보임) 때문에 그 Day는 다시 풀기도 '완료' 표시도 할 수 없게 된다. 제안: 가져올 때 다시 풀기 대상이 아닌 문항 중 맞힌 수로 첫 점수를 채운다.
2. **기록 백업:** 기준 사본은 프로젝트 파일만 담고, 브라우저에 있는 학습 기록은 담지 않는다. 제안: 저장 형식을 바꾸는 단계(U2) 전에 지금 앱에서 '기록 내보내기'로 파일을 받아 둔다.
3. **예전 탭 위험 설명 고치기:** 계획은 '예전 코드 탭이 새 필드를 지우면 깃발만 사라진다'고 적었다. 실제로는 복습으로 고친 문항의 틀린 횟수도 사라져, 첫 풀이가 끝나지 않은 Day의 첫 점수가 오를 수 있다. 제안: 설명을 고치고, 만들지 않는다는 결정은 유지한다.
